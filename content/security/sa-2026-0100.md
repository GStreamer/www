## Details

The RTP depayloader for uncompressed raw video streams did not validate the image dimensions negotiated from the media description of the stream. The range checks applied to each payload fragment mixed signed and unsigned arithmetic in a way that silently disabled them when the negotiated dimensions were smaller than the sampling increments of the negotiated format. A sender could then place payload fragments far outside the reassembled output frame, causing out-of-bounds writes, or trigger a copy of more than two gigabytes into the frame buffer. Both the dimensions and the fragment positions are fully attacker-controlled.

## Impact

An unauthenticated remote attacker, for example a malicious RTSP server or anyone able to inject RTP packets, can crash the application and cause denial of service simply by serving a stream whose description declares small image dimensions. Since the depayloader is auto-plugged by decodebin-based pipelines, opening a malicious URL is sufficient. The out-of-bounds writes are large and controllable enough that heap corruption and potentially arbitrary code execution cannot be excluded, although no such exploitation has been demonstrated.

## Solution

The gst-plugins-good 1.28.9 release addresses the issue. People using older versions of GStreamer should apply the patch and recompile.
